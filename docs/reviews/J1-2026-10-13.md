# J1 — `guests.html` Export CSV threw instead of downloading

**Symptom:** clicking **Export CSV** on the guest list raised
`TypeError: Failed to execute 'createObjectURL' on 'URL': Overload resolution failed.`
The file still landed in the downloads tray, but the handler aborted on its last statement, so the
object URL it created was never released (a leak per click) and the click pass recorded the control
as *"threw"*.

Status: **Fixed** · Date: 2026-10-13 · Route: `guests.html`

## Root cause

`src/js/guests.js:61` built the CSV, created a blob URL, clicked a synthetic download anchor — and
then ended with:

```js
a.click();URL.createObjectURL(a.href)
```

`URL.createObjectURL` was called with the **string** it had just stored in `a.href` (it expects a
`Blob`/`MediaSource`), so the browser threw on the overload. The verb is the bug: every other export
in this codebase revokes the URL after the click, e.g. `collaboration-v24.js:40`,
`studio-automation-v27.js:20`, `bundle-responses-v15.js:320`.

## Change

```diff
--- a/src/js/guests.js
+++ b/src/js/guests.js
-    a.download='guest-list.csv';a.click();URL.createObjectURL(a.href)};
+    a.download='guest-list.csv';a.click();setTimeout(()=>URL.revokeObjectURL(a.href),1000)};
```

`setTimeout(…, 1000)` rather than an immediate revoke: revoking synchronously can cancel the
download in some browsers, and 1000 ms is the pattern the rest of the repository already uses.
