# J2 — every editor tool click threw `root.querySelectorAll is not a function`

**Symptom:** clicking any button in the editor's tool rail (`↖V`, `TT`, `▣F`, `○O`, `╱L`, `✋H`,
`⌕Z`) raised `Uncaught TypeError: root.querySelectorAll is not a function or its return value is
not iterable`. The click still took effect, so the defect hid behind working buttons; it showed up
in the click pass as *"threw"* rather than as a dead control.

Status: **Fixed** · Date: 2026-10-13 · Route: `index.html` (editor / Design Studio)

## Root cause

`src/js/editor/ui-layout.js` has

```js
function keepActiveToolVisible(root = document) { $$('.ei-tool-rail', root)… }
```

and wired it like this:

```js
if (event.target.closest('.ei-tool-rail button')) requestAnimationFrame(keepActiveToolVisible);
```

`requestAnimationFrame` invokes its callback with a **`DOMHighResTimeStamp`**, so `root` received a
number instead of a `ParentNode` and the first `root.querySelectorAll` inside `$$` threw. Captured
stack (before the fix, from `artifacts/probe_j_j_errors.mjs`):

```
Uncaught TypeError: root.querySelectorAll is not a function or its return value is not iterable
    at $$ (bundle-index-v15.js:11258:54)
    at keepActiveToolVisible (bundle-index-v15.js:11380:5)
```

`keepActivePageVisible()` is called the same way on the line above, but it takes **no** argument, so
it was unharmed — only the tool-rail call site needed to change.

## Change

```diff
--- a/src/js/editor/ui-layout.js
+++ b/src/js/editor/ui-layout.js
-      if (event.target.closest('.ei-tool-rail button')) requestAnimationFrame(keepActiveToolVisible);
+      // The callback is wrapped: requestAnimationFrame invokes it with a DOMHighResTimeStamp,
+      // which used to land in keepActiveToolVisible's `root` parameter and throw
+      // "root.querySelectorAll is not a function" on every tool click.
+      if (event.target.closest('.ei-tool-rail button')) requestAnimationFrame(() => keepActiveToolVisible());
```

## Verification — `artifacts/probe_j_j_errors.mjs`

Before: all seven tool buttons (`○O`, `╱L`, `✋H`, `⌕Z`, `TT`, `▣F` were exercised individually)
produced the TypeError. After: **no error is reported for any of them** (the probe collects
`error` and `unhandledrejection` per click and prints a line only when one arrives; the post-fix run
printed none).

`python3 build.py all` → **0**; `python3 build.py all --check` → **0**.
The full 16-route sweep is re-run at the end of this pass (see `docs/reviews/final-report.md`) so the
*j-threw* entries are re-measured from the served bundle, not from this single-page probe.

## UNVERIFIED

The fix removes the exception; it does not assert that the active tool is scrolled into view in
every rail-overflow case (the function's purpose). That behaviour needs rails that actually overflow,
which the 1280 px probe does not produce; it is left as measured-not-asserted.
