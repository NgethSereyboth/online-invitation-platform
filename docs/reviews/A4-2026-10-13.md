# A4 — account.html on a signed-out load (2026-10-13)

**Status: FIXED.** A signed-out visit to `account.html` now shows a real signed-out state instead of
telling the visitor the server is missing.

Measured on the working tree at 2026-10-13, server `http://127.0.0.1:4175`,
`python3 build.py all --check` exit 0. Re-runnable:
`node artifacts/probe_a4_signed_out.mjs` (sweeps all 16 routes, then asserts the account page in both
session states).

---

## 1. The logged symptom needed correcting first

The inventory entry said a signed-out load "collapses its `<main>` element". It does not. Measured
(`artifacts/probe_a4_signed_out.mjs`, before the fix):

```
account.html      online   844     YES  Full server requiredAuthentication required
```

`<main>` is visible, 844px tall, `display:block` — what happens is that its **contents are replaced**
by a single box. On the way in, the same probe records for every route:

```
A4 before: routes with <main> not visible: none
```

So the defect is not layout collapse, it is *what the page says* and *what is left to do on it*: the
page's eight `.account-card` sections (profile, plan usage, password, security, sessions, passkeys,
privacy export, studio identity) and their controls are all replaced by a notice that reads
**"Full server required"** — on a server that is answering `/api/health` 200 and
`/api/auth/me` `200 {"user":null}`.

## 2. Root cause

Two facts combine:

1. `EInviteBackend.message(target, text)` (`src/js/backend-mode-v14.js`) builds
   `<section class="server-required-v14"><strong>Full server required</strong><p>{text}</p>` and calls
   `host.replaceChildren(box)`. The heading is hard-coded: **every** use of this helper claims the
   server is missing, whatever the caller's actual reason was.
2. `src/js/account.js` used that helper as its generic error renderer for the whole page:

   ```js
   catch (error) { EInviteBackend.message(main, error.message || _txt('Sign in through the full
                   application server to manage this account.')) }
   ```

   (and, since A1, the shell answers session-only requests locally with the same
   `401 {"error":"Authentication required","code":"unauthenticated"}` the server would have sent, so
   the failing request is now `/api/account/usage` rather than a 401 from the wire — the same catch,
   the same notice).

So `error.message` — the *401 body's* text — is what the notice's `<p>` shows, under a heading that
contradicts the actual state. A signed-out visitor is told the application server is missing.

The code's own intent was visible in the line `if(!me.user)throw Error('Sign in required')`: the page
*knows* the difference between "no session" and "no server" and then renders both the same way.

## 4. Fix — `src/js/account.js` only

**a. Say what the state means.** A signed-out state that keeps the page frame:

```js
function renderSignedOut(){
  const main=document.querySelector('main')||document.body; … if(grid)grid.hidden=true;
  … a <section class="account-card account-signed-out" data-signed-out="1"> with
       <h2>Sign in</h2>
       <p class="download-note">Sign in through the full application server to manage this account.</p>
       <a class="button-link account-sign-in" href="dashboard.html"><button class="primary">Sign in</button></a>
  … main.querySelector('.server-required-v14')?.remove();
}
```

`<main>` keeps its `<h1>`, its intro paragraph and a panel with the state and the way out; the eight
session-only cards are hidden (`hidden` is honoured by the global `[hidden]{display:none!important}`
in `src/css/accessibility.css`, so no new CSS was needed). Both strings already exist in
`docs/i18n/TRANSLATIONS.csv` — `Sign in` (dashboard.html) and `Sign in through the full application
server to manage this account.` (already attributed to `src/js/account.js`) — and both are used with
this file's existing `_txt(en, en)` fallback convention, so **no Khmer was invented and no CSV row was
added**.

**b. Ask before fetching.** After the offline check, the page now decides from the session it already
caches (`EInviteBackend.hasSession()`, one `/api/auth/me` per load, which the A1 work added for exactly
this) instead of discovering it through a failed request:

```js
if(window.EInviteBackend?.hasSession && !(await window.EInviteBackend.hasSession())){renderSignedOut();return}
```

**c. Route the failure, don't mislabel it.** The generic catch keeps its notice for genuinely unknown
failures, but the shell's own 401 now goes to the signed-out state:

```js
catch(error){ if(/authentication required|unauthenticated|sign in required|401/i.test(String(error?.message||''))){renderSignedOut();return}
             EInviteBackend?.message(main, error.message || …) }
```

The offline branch (`!isAvailable()`) is deliberately unchanged: there the "full server required"
heading is the truth.

## 7. Open items and UNVERIFIED (named)

1. **`analytics.html` still shows "Full server required" over an online server**, for a caller-supplied
   reason ("Open analytics from a specific invitation."). Measured above, not fixed here (out of A4's
   scope). The real fix is for a caller-state hint not to be expressed through a helper whose heading is
   about the server.
2. **`EInviteBackend.message()` is still a blunt instrument.** This task fixed its two callers on
   `account.html` (the label is now only used for the offline case); other callers were not audited
   beyond the 16-route sweep above, which found no further occurrence.
3. **No screenshot was taken for this item.** The evidence is DOM-level (panel presence, `<main>`
   height, the notice's absence, a real signed-in render). A visual pass over the new panel's styling
   inside the account page grid was not done; it reuses the existing `.account-card` and
   `.download-note` classes and the same `button-link`/`primary` markup the dashboard's signed-out
   block uses, but that is a reasoning step, not a measurement.
4. **Khmer rendering of the new panel** relies on `_txt(en, en)` — i.e. the accepted English fallback
   the rest of this file already uses. The panel is not translated, and it does not pretend to be.
