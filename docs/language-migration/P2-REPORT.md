## 1. How the inventory was recovered (and why it cannot be a grep)

`src/python/server.py` has **no route table**. Every route is an `if` inside a
`do_GET` / `do_POST` / `do_PUT` / `do_DELETE` chain that calls helper dispatchers
(`platform_v32_get`, `future_v52_get`, `_admin_get_dispatch`, `_put_admin_routes`,
…). The real ordering matters: `future_v52_get` runs **before** `platform_v32_get`,
which runs before every inline `path ==` test, and `PAGE_ALIASES` is consulted only
after `/` and `/uploads/`.

`tools/route-inventory.py` therefore:

1. indexes every `def` by indentation,
2. walks reachability from each `do_<METHOD>` through `self.<helper>(path)` calls, so a
   route declared in `_admin_get_dispatch` is attributed to GET, not to all four,
3. extracts five declaration forms — `path == "…"`, `path in {…}`,
   `path.startswith(…)` plus its `endswith`/`in path` conditions, `re.fullmatch(…)`,
   and `{"/path": self.handler}` dispatch dictionaries,
4. classifies auth from guard symbols in the handler **and its callees** (depth 3),
   because handlers delegate (`ai_agent_tools` → `_ai_agent_access` → `require_user`),
5. optionally probes the running backend, **GET only**, skipping routes that generate
   artefacts (`/api/media`, `/api/image`, social cards, exports, backups, `*.png/svg/ics`).

An earlier revision of the tool reported 203 declarations for each of the four methods.
That was a def-range bug (a new `def` did not close the previous block), not a real count;
it was found by refusing to accept an impossible shape (four identical counts).

## 3. Trailing-slash behaviour — verified, not inferred

125 GET declarations were probed against the live local backend
(`http://127.0.0.1:4175`), each twice: as declared, and with one trailing slash appended.
**88 pairs differ.** The rule the backend actually implements:

> An **exact** `path == "/api/…"` route matches only the exact string. The same path with a
> trailing slash falls through every branch and lands on the final 404.
> A **regex** route ending in `/?` accepts both forms.

Evidence (identical shape across account, admin, studio, catalog and auth routes):

| Route | as declared | + trailing slash |
|---|---|---|
| `GET /api/account/api-keys` | 401 | **404** |
| `GET /api/account/sessions` | 401 | **404** |
| `GET /api/admin/metrics` | 401 | **404** |
| `GET /api/auth/me` | 200 | **404** |
| `GET /api/feature-flags` | 200 | **404** |
| `GET /api/health` | 200 | **404** |
| `GET /_marketplace/crl.json` | 200 | **404** |
| `GET /api/invitations/<id>/gift-registry` (`/?` regex) | 403 | 403 |

Two consequences for the migration:

1. **D6 ("byte-identical, no exceptions") now has a concrete, testable meaning.** A Node
   router that normalises trailing slashes (Fastify does not, but `ignoreTrailingSlash`
   would) changes 88 observable behaviours at once. It must stay off, or the inventory
   must record each exception deliberately.
2. The probe cannot distinguish *which* auth guard produced a 401 — only that routing
   matched. Status parity on unauthenticated probes is a routing test, not an auth test.

Probe limits, recorded as known gaps: 18 GET declarations were skipped (artefact-generating
routes), 1 timed out (`/api/invitations/<id>/campaigns/<id>/deliveries`), and POST/PUT/DELETE
were **not** probed at all — they are writes and the origin is the owner's live data. Their
status behaviour must be established by S1's harness against a disposable instance.

## 4. Auth classes — what the 36 "platform service" rows mean

The scan found a guard symbol for 334 of 345 declarations. The 36 rows labelled
`platform-service` are `/api/platform/v32/*`, `/api/platform/v52/*` and the
collaboration/raster families: their guard is **not in `server.py`**, it lives behind
`get_platform_v32_service()` / `get_future_v52_service()`.

This is a correction to the plan's implied model of the auth boundary. S9 ("auth domain")
and S6 ("session/CSRF interop") must port the guard from `src/python/platform_v32/`, not
from the dispatcher, or those 36 routes will be ported with no authentication at all.

### 4.1 The 11 rows that need a manual read before any port

| Method | Pattern | Note |
|---|---|---|
| DELETE | `/api/templates/` | prefix fallthrough; `delete_template` carries no guard symbol |
| GET | `/api/canva/export-formats` | no guard in handler |
| GET | `/api/invitations/<id>/campaigns/<id>/deliveries` | no guard; handler reads `list_campaign_deliveries` |
| GET | `/api/template-marketplace` | no guard in handler |
| GET | `/api/template-marketplace/<id>` | no guard in handler |
| GET | `/favicon.ico` | genuinely public (204) |
| POST | `/api/analytics/events` | public beacon; confirm rate limit instead of auth |
| POST | `/api/invitations/` ×3 | `claim_signup_slot`, `vote_poll`, `moderate_album_photo`, `create_signup_sheet`, `create_poll` — guest-token routes, guard is per-guest not per-user |
| POST | `/api/platform/v32/` | delegation to the service |

None of these is a defect; they are the rows where the mechanical classifier cannot
decide, and they are exactly what S1's harness must exercise first.

## 5. Page reconciliation — 16 vs 17, `PAGE_ALIASES`, fixtures

`src/python/*.html` holds **27 files**, which reconciles the plan's 16-vs-17 disagreement:

| Group | Count | Files |
|---|---|---|
| Product pages | **16** | `index`, `dashboard`, `designer`, `templates`, `guests`, `responses`, `materials`, `checkin`, `analytics`, `admin`, `account`, `billing`, `privacy`, `public`, `reset`, `verify` |
| Test fixtures | **11** | `test-a`…`test-d`, `test-i18n-beacon`, `test-i18n-click`, `i18n-css-en`, `i18n-css-km`, `i18n-css-test`, `i18n-inject-test`, `dashboard-css-km` |

`PAGE_ALIASES` has **15 entries** (every product page except `/`, which is served before
the alias lookup). Extensionless aliases go through the map; explicit `.html` requests go
through `re.fullmatch(r"/[A-Za-z0-9_.-]+\.html")` → `serve_html_file`, which will serve any
existing page file by name — **including the 11 fixtures**.

**Decision for S3 (recommended, needs owner sign-off under D6):** keep the passthrough
byte-identical (it is observable behaviour, and `test-a.html`…`test-d.html` are used by
browser runners), but **exclude the 11 fixtures from the S3 parity corpus**. They are test
scaffolding, not product surface; including them would freeze test files into a contract the
Node service must honour forever. Product parity is the 16 pages + `PAGE_ALIASES` + `/` +
`/uploads/` + `/api/health` + the missing-`/i/<slug>` 404 (`no-store`, `noindex`).
