Privacy

This platform is designed so invitations can operate without collecting unnecessary guest information. The invitation owner controls whether optional analytics and external media are enabled.

Invitation visits

When an invitation requires analytics consent, a visit is not added to its view statistics until the guest chooses to allow analytics. The platform records aggregate visit events rather than advertising profiles.

Guest information

RSVP is optional. When enabled, the host may collect information needed for the event, such as attendance, guest count, meal, transport or accommodation preferences. Guest wishes are independently optional. Invitation owners should request only information they genuinely need.

External media

YouTube and SoundCloud are external providers. When external-media consent is required, those providers are not loaded until the guest allows them. Provider privacy terms then apply to the embedded content.

Personalized invitation links

Personal guest links may contain a short-lived or revocable credential. They should be treated like private invitation links. General sharing controls remove personalized and private-access parameters.

Account controls

Account holders can review active sessions, export their data, configure privacy preferences, and schedule account deletion. Deleted invitations use a recovery period before permanent purge where configured.

Storage and retention

Uploaded files can be stored locally or through a configured private object-storage provider. Production operators are responsible for configuring encryption, lifecycle policies, backups, legal retention requirements and their own public contact information.

Creator analytics

E-invitation-website provides first-party creator analytics so hosts can see how their invitations performed: how many people opened the invitation, how long they engaged, where they came from, and which device class they used. Analytics are enabled by default; the host may turn them off per invitation at any time.

What analytics collects (and what it does not):

  • Session id — a 128-bit random hex value stored in sessionStorage. Resets on tab close. Used only to group events from a single page visit.
  • Invitation id — which invitation the visit belongs to.
  • Recipient id — an opaque guest id (not an email), only when the visitor used a personalized guest link.
  • Coarse country — derived from the IP address, then discarded. The IP address itself is never stored.
  • Referrer domain — the bare hostname (e.g. facebook.com), not the full URL.
  • Device class — mobile / tablet / desktop only, derived from the User-Agent.
  • Engagement metrics — session duration (measured from page load to page unload), maximum scroll depth (0–100%), and a small set of event types (RSVP open, RSVP submit, gallery open, album upload, etc.).

What analytics does not collect: IP addresses, cookies for tracking, advertising IDs, cross-site identifiers, precise location, email addresses, names, or any third-party tracker.

Analytics data is retained for a maximum of EINVITE_ANALYTICS_RETENTION_DAYS (default 365 days) and is automatically pruned thereafter. Hosts can export their raw data as CSV or JSON, and may purge all collected analytics data for an invitation at any time.

For the full event model and technical details, see Event Model and Analytics Privacy.
