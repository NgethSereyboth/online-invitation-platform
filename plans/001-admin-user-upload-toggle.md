## Why this matters

The per-account upload permission is fully implemented on the server (`PUT /api/admin/users/{id}/uploads`, which writes `users.upload_enabled` and writes an audit event). The live admin Users page (`src/js/pages/admin/users.js`) never got the matching control, so an administrator cannot turn uploads off for an account from the page they actually use. The only UI is in the legacy `src/js/admin.js`, which is not the served page. The test `tests/v0_52_upload_permission_test.py` fails at its line 162 because the bundled admin JS lacks the markers. `make check` still passes because the bundle is in sync with its (incomplete) sources. After this plan, the control exists in the source, the bundle is regenerated, and the test passes.

## Current state

1. `src/js/pages/admin/users.js` is the source for the Users tab. Its per-row actions (inside `render()`) are only: suspend/unsuspend, reset-password, force-mfa, impersonate. There is no upload checkbox and no upload save button. Its `handleAction(btn)` dispatches on `btn.dataset.action`, reads `userId` from `closest('[data-user-id]')`, and calls `api.send(url, 'POST', body)`.

   Use this as the behavioral reference only; do not copy its code style.

```js
} else if (action === 'save-uploads') {

}
```

Keep the existing `try/catch` (it alerts on error). Do not add a confirm dialog (the legacy page does not have one for this action; keep behavior consistent with it).
