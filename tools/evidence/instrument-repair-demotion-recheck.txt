INSTRUMENT REPAIR — Goal 1: the one candidate the expanded sweep called
unanimously demotable, and why it is not demoted.

The candidate: 'transform' in
  .ui-theme-menu button:hover { background: var(--app-surface-3) !important; transform: none !important }
which the sweep on the fixed (v3) probe reported redundant in all 3 runs on all
16 pages — 48 of 48. It is the only declaration in the sweep's demotable set.

Two defects made that unanimity vacuous, and the tool below is what measures the
declaration where the sweep cannot:

  (a) every element the rule reaches is inside a display:none subtree (the theme
      menu carries [hidden] until the user opens it), and Chrome does not resolve
      used values for an element with no box — so 'transform' reads none whatever
      the cascade says. The probe now reports this as UNMEASURED (v4), with the
      count of elements reached and no box.
  (b) the probe's own self-check fixture lives in the page while the sweep runs
      (div.ui-theme-menu.decl-fixture-host > button), and that element matches
      this very selector: it was measured as a target of the real rule. The probe
      now tears its fixture down before the sweep (v4) and asserts it is gone.

3. WHAT THE CASCADE SAYS: WHY THE DELETE DIFFERS FROM THE DEMOTE
=====================================================================
cmd: node tools/css-cascade-winner.mjs http://127.0.0.1:8124/index.html --selector='.ui-theme-menu button' --property=transform --states=plain,hover
CASCADE_HOVER_MEDIA {"hoverCapableByDefault":false,"clausesFound":2,"rewritten":2,"stillInactiveAfter":0}
CASCADE_WINNER {"url":"http://127.0.0.1:8124/index.html","selector":".ui-theme-menu button","property":"transform","elements":2,"index":0,"states":["plain","hover"]}
  state=plain         computed transform="none"
    last-important -> (none)
  state=hover         computed transform="none"
    order=22           transform          translateY(-2px) scale(1.012)                        button:not(:disabled):hover, .cta:hover, .secondary:hover, .action:hover
    order=23 IMPORTANT transform          none!important                                       .ui-theme-menu button:hover
    last-important -> .ui-theme-menu button:hover  transform:none!important

  order=22 is the @media(hover:hover) rule and order=23 the declaration, in the SAME
  sheet, at the SAME specificity (0,2,1). So a demotion — dropping only the priority
  — would leave this declaration winning the tie by source order (which is why
  VALUES_AFTER_DEMOTION above is unchanged), while deleting it hands the property to
  the lift. That distinction is exactly why the sweep's model of the change (remove
  the declaration) is the STRONGER test, and why a declaration that fails it is not
  demoted on the strength of a page state where nothing is observable.
